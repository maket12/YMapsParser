Техническое задание: Парсер Яндекс.Карт (по ссылке)
Цель: разработать парсер Яндекс.Карт с интеграцией в Телеграм-бот. Бот принимает ссылку с Яндекс.Карт (search URL), собирает данные и выдает Excel-файл (XLSX). Файл содержит три листа: «Выдача», «Организации», «Отзывы». Ключ для связи данных между листами — org_id.
Функциональные требования
    1. 1. Пользователь отправляет в бота ссылку поиска Яндекс.Карт (search URL).
    2. 2. Парсер извлекает все организации из этой выдачи и собирает их карточки и отзывы.
    3. 3. В Excel добавляется поле search_url, чтобы было понятно, откуда получены данные.
    4. 4. После запуска бот сообщает примерное время выполнения (ETA), исходя из числа организаций.
    5. 5. Парсер работает с троттлингом: задержка 3–7 сек, повторы 2–3 раза при ошибке.
    6. 6. При появлении капчи разработчик обязан реализовать её решение самостоятельно (без участия пользователя).
    7. 7. Сессии (cookies) сохраняются между запусками для снижения вероятности капчи.
    8. 8. Временные файлы Excel удаляются после отправки пользователю (если не указан режим архивации).
    9. 9. Логи: бот фиксирует шаги, ошибки, где остановился.
    10. 10. Автозапуск через systemd: бот поднимается автоматически при рестарте сервера.
Лист 1: «Выдача»
    • search_url — ссылка поиска, которую ввёл пользователь
    • date — дата и время парсинга (YYYY-MM-DD HH:MM)
    • rank — позиция компании в выдаче
    • org_id — ID организации для связи с другими листами
    • name — название компании
    • rubric — рубрика/категория
    • rating — средний рейтинг (0–5)
    • reviews_count — количество отзывов
    • short_address — краткий адрес (улица, дом)
    • is_ad — признак рекламы (да/нет)
    • promo_text — текст акции, если указан
    • badges — бейджи (например, «Хорошее место»), через ;
    • has_online_booking — есть кнопка онлайн-записи (да/нет)
    • booking_label — текст кнопки записи
    • has_prices_button — есть кнопка «Цены» (да/нет)
    • price_service — услуга, отображаемая в чипе цены
    • price_value — стоимость услуги
    • price_currency — валюта
    • price_duration — длительность услуги
Лист 2: «Организации»
Основное
    • org_id — ID организации
    • name — название
    • rubric — основная рубрика
    • full_address — полный адрес (город, улица, дом)
    • lat — широта
    • lon — долгота
    • phones — телефоны, через ;
    • site — сайт
    • schedule — расписание (7 строк в одной ячейке)
    • is_open_now — открыто сейчас (да/нет)
    • description — текст описания
Медиа
    • photos_count — количество фото
    • has_video — наличие видео (да/нет)
    • videos_count — количество видео
    • has_stories — наличие историй (да/нет)
    • stories_titles — названия историй, через ;
Услуги
    • services_count — количество услуг
    • services_list — названия услуг, через ;
    • services_prices — цены услуг, через ;
    • services_has_photos — наличие фото у услуг (да/нет)
    • services_with_photos — услуги с фото, через ;
    • services_has_covers — наличие обложки у услуг (да/нет)
    • services_description_filled — наличие описания у услуг (да/нет)
Новости
    • has_news — наличие новостей (да/нет)
    • news_count — количество новостей
    • news_titles — заголовки новостей, через ;
    • news_texts — тексты новостей, разделённые |||
    • news_dates — даты новостей, через ;
Особенности
    • has_features — наличие вкладки «Особенности» (да/нет)
    • features_list — список особенностей, через ;
Дублированные метрики
    • rating — рейтинг
    • reviews_count — количество отзывов
    • card_url — ссылка на карточку
Лист 3: «Отзывы»
    • org_id — ID организации (связь с листом «Организации»)
    • review_id — ID отзыва
    • review_date — дата отзыва (YYYY-MM-DD)
    • stars — оценка (1–5)
    • text — текст отзыва
    • has_owner_reply — наличие ответа владельца (да/нет)
    • owner_reply_text — текст ответа владельца
    • owner_reply_date — дата ответа владельца
Правила
    11. Все данные выгружать в один XLSX с тремя листами.
    12. Ключ для связи между листами — org_id.
    13. Пустые значения оставлять пустыми (не писать «нет данных»).
    14. Разделители: ; для списков, ||| для текстов новостей.
    15. Кодировка UTF-8.
